ℹ️ Informações Importantes

Erro "UNIQUE constraint failed": Este é um comportamento esperado quando você tenta criar um usuário com email ou username que já existe no banco de dados.

Para resetar o banco: Pare o servidor, delete o arquivo database.sqlite e reinicie o servidor.

🔧 AUTO-MIGRAÇÃO: O sistema verifica e cria automaticamente a coluna 'role' se necessário.

🛡️ Usuário Admin: Clique no botão vermelho "Criar Admin" para criar usuário admin com credenciais: admin/admin

⚠️ MODO TESTE: Todas as operações estão liberadas para facilitar testes. Em produção, haverá autenticação rigorosa.

🔄 Reset de ID: "Apagar Todos" também reseta o autoincrement - próximo usuário criado terá ID = 1.

📱 Sessão Persistente: Ao fazer login, sua sessão é salva automaticamente e restaurada ao recarregar a página.

Usuários de exemplo já criados: gandalf, strider, elfprince, shieldmaiden

Login: Aceita tanto email quanto username (ex: admin ou admin@diceordie.com)

🛡️ Sistema de Segurança Implementado:

  • ✅ Controle de acesso baseado em roles (user/admin)
  • ✅ Primeiro usuário = Admin automático
  • ✅ Perfis públicos para interação social (sem dados sensíveis)
  • ✅ Dados sensíveis protegidos (email, data nascimento)
  • ✅ Edição/exclusão restrita ao próprio perfil ou admin
  • ✅ Auto-migração de schema do banco de dados

Permissões por Tipo de Usuário:

  • 🌍 Todos: Ver perfis públicos, buscar usuários
  • 👤 User: Editar/apagar próprios dados + permissões públicas
  • 🛡️ Admin: Acesso total + operações administrativas

Dados Públicos vs Privados:

  • 🌍 Públicos: Nome, username, gênero, experiência, role, foto
  • 🔒 Privados: Email, data nascimento (apenas próprio perfil)
